# 专栏导入标准逻辑（产品需求文档）

> 适用范围：BlogLoom 后台「专栏管理 → 导入 ZIP」的标准用户导入流程。
> 对应实现：`ColumnArchiveServiceImpl`、`ColumnAdminController`、`ColumnCoverStorageService`，前端 `ColumnManage.vue`。
> 关联功能：专栏导出（`GET /admin/columns/export`），导入/导出结构互逆。

---

## 一、背景与目标

博客专栏支持多级结构，用户往往需要一次性把已有的专栏体系（含名称、简介、图标、层级）迁移到 BlogLoom。
手工逐个创建成本高、易错，因此提供「专栏 ZIP 一键导入」能力：

- 用户只需准备一个符合标准的 ZIP 包，即可批量创建一级专栏与子专栏；
- 导入前提供「预检」，让用户确认将导入的内容与图标缺失情况，避免误操作；
- 提供同名冲突策略与「前台展示」开关，兼顾重复导入与灰度上线的诉求。

---

## 二、名词定义

| 名词 | 说明 |
| --- | --- |
| 专栏 ZIP | 用户上传的压缩包，必须包含 `columns.json`，可选 `icons` 图标目录 |
| columns.json | 定义专栏层级结构的 JSON 文件，是导入的唯一数据来源 |
| 一级专栏 | `parent_id = 0` 的专栏 |
| 子专栏 | 挂在一级专栏下的专栏，系统最多支持两级 |
| 预检 | 上传后仅解析与校验、不写库的阶段，返回统计与路径列表 |
| 冲突策略 | 目标层级下已存在同名专栏时的处理方式：跳过（SKIP）或自动重命名（RENAME） |
| 前台展示 | 对应 `blog_column.is_published`，关闭时前台不可见 |

---

## 三、入口与交互

入口：后台「专栏管理」页面右上角「导入 ZIP」按钮，打开「导入专栏 ZIP」弹窗。

弹窗为三步式向导：

1. **选择文件与配置**：拖拽/选择 ZIP，设置「同名专栏」策略与「前台展示」开关，可下载模板 ZIP 参考；
2. **内容预检**：展示预检统计（一级专栏数、子专栏数、图标数、缺失图标数）与即将导入的专栏路径列表；
3. **执行导入**：确认后执行，展示结果（新增一级专栏、子专栏、导入图标、跳过数量）。

对应接口：

| 步骤 | 接口 | 说明 |
| --- | --- | --- |
| 预检 | `POST /admin/columns/import/preview` | 表单：`file`、`conflictPolicy`（默认 SKIP）、`published`（默认 true） |
| 执行 | `POST /admin/columns/import/{token}/execute` | 凭预检返回的 `token` 执行 |
| 导出 | `GET /admin/columns/export` | 导出 `columns.zip` |

## 四、标准输入物规范

### 4.1 ZIP 目录结构

```
columns.zip
└── columns/                 # 目录名不限，可为空
    ├── columns.json         # 必需，文件名固定
    └── icons/               # 可选，图标目录
        ├── tech.png
        ├── frontend.png
        └── ...
```

- `columns.json` 可以位于 ZIP 内任意目录（按文件名识别，忽略大小写），但**只能有一个**；
- `icon` 字段的路径解析规则：
  1. 先按「相对 ZIP 根目录」查找；
  2. 未命中时再按「相对 columns.json 所在目录」查找；
  3. 路径忽略大小写，兼容 `\` 与 `/`，自动去除前导 `/`。

### 4.2 columns.json 字段规范

JSON 顶层为数组，元素为一级专栏；每个元素可含 `children` 数组，`children` 下不允许再嵌套（最多两级）。

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `title` | string | 是 | 去空格后非空，≤ 100 字符 | 专栏名称，同一父级下不可重名 |
| `description` | string | 否 | ≤ 500 字符 | 专栏简介，缺省写空串 |
| `icon` | string | 否 | jpg/jpeg/png/webp，≤ 5MB | 图标相对路径 |
| `order` | int | 否 | — | 同级排序值，越小越靠前；缺省时追加到末尾 |
| `children` | array | 否 | 仅一级专栏可含 | 子专栏列表，结构同上，不可再嵌套 |

标准示例（与模板 ZIP 一致）：

```json
[
  {
    "title": "技术笔记",
    "description": "记录日常技术学习与踩坑总结",
    "icon": "icons/tech.png",
    "order": 1,
    "children": [
      {
        "title": "前端开发",
        "description": "HTML、CSS、JavaScript 与前端工程化",
        "icon": "icons/frontend.png",
        "order": 1
      },
      {
        "title": "后端开发",
        "description": "Java、数据库与服务端架构",
        "icon": "icons/backend.png",
        "order": 2
      }
    ]
  },
  {
    "title": "生活随笔",
    "description": "记录生活感悟与个人思考",
    "icon": "icons/life.png",
    "order": 2
  }
]
```

### 4.3 文件与安全限制

| 项 | 限制 |
| --- | --- |
| ZIP 文件大小 | ≤ 100 MB |
| 单个文件大小 | ≤ 5 MB |
| 解压总大小 | ≤ 200 MB |
| columns.json 大小 | ≤ 2 MB |
| ZIP 原始 Entry 数 | ≤ 10000 |
| 路径最大深度 | ≤ 10 层 |
| 编码 | columns.json 必须为合法 UTF-8 |
| 路径安全 | 禁止绝对路径、盘符路径、`..`、`.`、空路径段、`\0` |
| 自动忽略 | `__MACOSX/` 及任一路径段以 `.` 开头的文件（如 `.DS_Store`） |
| 重名路径 | ZIP 内出现重名路径（忽略大小写）直接判为非法 |

## 五、标准导入流程

### 5.1 预检阶段（不写库）

1. 校验导入参数：`conflictPolicy` 仅允许 `SKIP`/`RENAME`；`published` 缺省为 `true`；
2. 校验文件：非空、≤ 100MB、扩展名为 `.zip`；
3. 将上传流写入临时文件（预检与执行都基于该临时文件）；
4. 扫描 ZIP：
   - 过滤目录、隐藏文件、`__MACOSX`；
   - 定位并唯一性校验 `columns.json`；
   - 校验各文件大小、总大小、Entry 数、路径合法性；
5. 解析并校验 `columns.json`（见第六节校验规则），统计一级专栏、子专栏、有效图标、缺失图标；
6. 生成一次性 `token`，缓存预检会话（含临时文件、解析结果、参数），有效期 **30 分钟**；
7. 返回预检结果：`token`、`rootCount`、`childCount`、`iconCount`、`missingIconCount`、`paths`。

> 预检失败会立即删除临时文件并返回明确的错误提示。

### 5.2 执行阶段

1. 凭 `token` 取出会话（一次性，取出即失效），校验存在且未过期；
2. 在**单个事务**内按顺序处理每个一级专栏：
   - 处理一级专栏（冲突判断 → 创建或复用）；
   - 应用一级专栏图标；
   - 遍历其子专栏，逐个执行同样的「冲突判断 → 创建/复用 → 图标」；
3. 返回统计结果：`createdRootCount`、`createdChildCount`、`skippedCount`、`importedIconCount`；
4. 无论成功失败，最终删除临时 ZIP。

> 执行是同步请求（前端超时 120s）；任一步骤异常则整体回滚，不产生部分数据。

## 六、核心处理逻辑

### 6.1 专栏创建规则

| 项 | 规则 |
| --- | --- |
| 层级 | 仅支持一级 + 子专栏两级；子专栏下再嵌套 `children` 视为非法 |
| 父级 | 一级专栏 `parent_id = 0`，子专栏 `parent_id = 对应一级专栏 id` |
| 名称 | 取 `title.trim()`；同父级下不允许重名（预检已拦截） |
| 简介 | 取 `description.trim()`，缺省为空串 |
| 排序 | `order` 有值则用 `order`；缺省则 `当前父级最大 sort + 10`，保证追加在末尾 |
| 前台展示 | 由导入参数 `published` 决定，缺省 `true`（即默认公开） |
| 封面 | 创建时先置空，随后按 `icon` 尝试写入 |

### 6.2 同名冲突处理

判断依据：**同一父级下、名称完全相同**。

| 策略 | 一级专栏 | 子专栏 |
| --- | --- | --- |
| SKIP（默认） | 复用已存在的一级专栏，跳过创建但**继续处理其子专栏**，并仍尝试更新其图标 | 跳过创建，计入 `skippedCount`，不处理图标 |
| RENAME | 生成 `原名 (1)`、`原名 (2)` … 直到不重名，再创建 | 同左 |

> 说明：一级专栏 SKIP 采用「复用 + 合并子级」语义，便于增量补充子专栏；子专栏 SKIP 采用「整体跳过」语义。

### 6.3 图标处理

1. 仅在专栏创建/复用成功后处理；
2. 按 4.1 的路径解析规则在 ZIP 中定位图标文件；
3. 校验扩展名（jpg/jpeg/png/webp）与大小（≤ 5MB）；
4. 保存到专栏图片目录，文件名为随机 UUID，避免覆盖；
5. 写回 `cover` 字段为正式访问 URL：`{api}/static/blogColumn/{专栏ID}/{uuid}.{ext}`；
6. 图标文件缺失或格式不支持时**不阻断导入**，仅不设置封面（预检的「缺失图标」数可提前提示）。

### 6.4 结果反馈

| 字段 | 含义 |
| --- | --- |
| `createdRootCount` | 新增一级专栏数 |
| `createdChildCount` | 新增子专栏数 |
| `skippedCount` | 因 SKIP 策略跳过的专栏数（含一级与子专栏） |
| `importedIconCount` | 成功导入的图标数 |

## 七、校验与错误提示（用户可见）

| 场景 | 提示 |
| --- | --- |
| 未选择文件 | 请选择 ZIP 文件 |
| 文件超限 | ZIP 文件不能超过 100 MB |
| 非 ZIP | 仅支持 ZIP 文件 |
| 缺少清单 | ZIP 中缺少 columns.json |
| 多个清单 | ZIP 中存在多个 columns.json |
| 清单为空 | columns.json 中没有可导入的专栏 |
| 清单编码错误 | columns.json 不是有效 UTF-8 编码 |
| 名称缺失 | 一级专栏/子专栏名称不能为空 |
| 名称超长 | 专栏名称不能超过100个字符 |
| 同级重名 | 同级专栏名称重复 |
| 简介超长 | 专栏简介不能超过500个字符 |
| 层级超限 | 专栏最多支持两级 |
| 单文件超限 | 文件不能超过 5 MB |
| 总量超限 | ZIP 解压总大小超过限制 |
| 路径非法 | ZIP Entry 路径不合法 / ZIP 不能包含绝对路径 |
| ZIP 内重名 | ZIP 内存在重名路径 |
| 会话失效 | 预检会话已过期或已提交 |
| 参数非法 | 导入参数不能为空 / 冲突策略不正确 |

---

## 八、边界与限制

- 导入是**全量追加**，不会删除或覆盖目标库中已有的其他专栏；
- 不提供异步进度与断点续传，一次性同步完成；
- 预检 token 一次性使用，30 分钟未执行即失效并清理临时文件；
- 系统定时（每 5 分钟）清理过期会话与临时文件；
- 导入结果通过操作日志记录（操作名「导入专栏」）。

---

## 九、验收标准

1. 上传标准模板 ZIP，预检展示一级/子专栏与图标统计正确，路径列表完整；
2. 执行后专栏树层级、名称、简介、排序、前台展示状态与 columns.json 一致；
3. 图标正确落库并以 `/static/blogColumn/{id}/...` 形式展示；
4. 选择 SKIP 且目标已存在同名一级专栏时，不新建该一级专栏，但其新子专栏被创建；
5. 选择 RENAME 时同名专栏生成 `(1)` 后缀且不覆盖原数据；
6. `published` 关闭时导入的专栏前台不可见；
7. 任一校验失败时给出明确提示且不产生任何脏数据（事务回滚）；
8. 导出 `columns.zip` 再导入，可还原等价专栏结构（导入/导出互逆）。
