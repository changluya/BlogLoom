# 博客迁移导入标准逻辑（产品需求文档）

> 适用范围：BlogLoom 后台「知识库 / 文章管理 → 快捷导入」的标准博客迁移导入流程，支持两种导入来源：
> **知识库 ZIP**（按压缩包目录结构还原）与 **Markdown 文件**（单个/多个，按 `knowledgeBasePath` 定位目录）。
> 对应实现：`MarkdownArchiveServiceImpl`、`KnowledgeImportWorker`、`KnowledgeArticleMetadataParser`、`KnowledgeBasePathSupport`、`KnowledgeNodeAdminController`，前端 `KnowledgeImportDialog.vue`。
> 关联功能：知识库导出（整库 ZIP / 单文档下载），导入/导出结构互逆。

---

## 一、背景与目标

用户通常已在本地积累大量 Markdown 博客，希望一次性迁移进 BlogLoom，并自动完成目录归类、文章属性补全与关联关系建立。
为此提供「博客迁移导入」能力：

- 用文件夹结构还原知识库目录树，用 Markdown 文件生成博客文章；
- 每篇博客通过顶部固定 JSON 代码块声明标题、标签、分类、摘要、专栏、创建/更新时间等元数据；
- 标签、分类在数据库不存在时自动创建并关联；**专栏只匹配已存在的专栏并关联，不自动创建**；
- 支持自定义文章的创建时间与更新时间（格式 `YYYY-MM-DD HH:mm:ss`），导入后归档与排序按真实时间生效；
- 提供预检、异步进度、同名冲突策略与「是否公开」开关。

---

## 二、名词定义

| 名词 | 说明 |
| --- | --- |
| 博客 ZIP | 用户上传的压缩包，仅识别文件夹与 `.md` 文件 |
| 元数据代码块 | 每篇 Markdown **最顶部**的 ```json 代码块，声明文章属性 |
| DIR 节点 | 知识库目录节点，对应 ZIP 内的文件夹 |
| DOC 节点 | 知识库文档节点，通过 `blog_id` 关联一篇博客 |
| 预检 | 上传后仅扫描与校验、不写库的阶段 |
| 进度任务 | 异步导入任务，前端按 taskId 轮询进度 |
| 冲突策略 | 目标目录下已存在同名文档时：跳过（SKIP）或自动重命名（RENAME） |

## 三、入口与交互

入口：后台「知识库」页面顶部「导入 Markdown ZIP」按钮，以及「文章管理」页面顶部「快捷导入」按钮（二者复用同一弹窗）。

三步式向导：

1. **选择文件与配置**：先选择导入来源——「知识库 ZIP」或「Markdown 文件」，再选择文件并设置「同名文档处理方式」「导入后直接发布」；
2. **内容预检**：展示目录数、Markdown 文档数、已过滤项目数、即将导入的路径列表；
3. **执行导入**：提交后进入进度页，实时展示进度、当前文件、已创建博客/目录/跳过数量。

对应接口：

| 步骤 | 接口 | 说明 |
| --- | --- | --- |
| 预检（ZIP） | `POST /admin/knowledge/import/preview` | 表单：`file`、`targetParentId`（默认 0=根目录）、`published`（默认 true）、`conflictPolicy`（默认 SKIP） |
| 预检（文件） | `POST /admin/knowledge/import/preview/files` | 表单：`files`（可多个 .md）、`targetParentId`、`published`、`conflictPolicy` |
| 执行 | `POST /admin/knowledge/import/{token}/execute` | 返回 `taskId` |
| 进度 | `GET /admin/knowledge/import/tasks/{taskId}` | 前端每 1 秒轮询一次 |
| 导出 | `GET /admin/knowledge/export` | 导出整库 `blogloom-knowledge.zip` |
| 单文档 | `GET /admin/knowledge/export/documents/{id}` | 下载单个文档 `.md` |

## 四、标准输入物规范

### 4.1 ZIP 目录结构

```
blogloom-knowledge.zip
├── Java/
│   ├── JVM内存模型.md
│   └── 并发编程.md
├── 数据库/
│   └── MySQL索引.md
└── 随笔.md
```

- 文件夹映射为 `DIR` 节点，`.md` 文件映射为 `DOC` 节点；
- 其他类型文件、隐藏文件（任一路径段以 `.` 开头）与 `__MACOSX/` 自动过滤；
- 若 ZIP 内所有内容都包裹在同一个顶层目录下，导入时会自动去掉该顶层目录；
- ZIP 内路径（忽略大小写）不可重名。

### 4.2 标准博客顶部代码块结构（重点）

每篇 Markdown **最顶部**使用一个 ```json 代码块声明元数据，结构固定如下：

````markdown
```json
{
  "title": "SqlParser解析器快速入门",
  "tags": "AI技术,SEO优化,内容营销",
  "category": "SqlParser",
  "articleSummary": "本文探讨了如何利用AI技术优化博客内容的SEO效果，帮助提升搜索引擎排名和读者吸引力。",
  "columns": "SqlParser, AI",
  "createTime": "2026-09-19 14:30:00",
  "updateTime": "2026-09-19 14:30:00"
}
```

# 正文标题

正文内容……
````

字段规范：

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `title` | string | 否 | 非空时作为标题 | 文章标题，缺省时回退为 Markdown 文件名（去掉 `.md`） |
| `tags` | string / array | 否 | 建议 3-5 个，高度相关 | 标签，多个；逗号分隔（支持 `, ，、| ; ；`），也可写数组 |
| `category` | string | 否 | 单个 | 分类，默认一个；缺省时使用默认分类「知识库」 |
| `articleSummary` | string | 否 | 150 字以内，含关键词 | 文章描述，缺省时由正文自动截取前 200 字兜底 |
| `columns` | string / array | 否 | 可多个 | 所属专栏，多个；逗号分隔，也可写数组。**仅关联数据库中已存在的专栏，不会自动创建** |
| `createTime` | string | 否 | 格式 `YYYY-MM-DD HH:mm:ss` | 文章创建时间，缺省为导入时间 |
| `updateTime` | string | 否 | 格式 `YYYY-MM-DD HH:mm:ss` | 文章更新时间，缺省同创建时间 |
| `knowledgeBasePath` | string | 否 | 严格格式 `/a/bb/cc`，以 `/` 开头、末尾不带 `/` | 知识库目录路径。**仅「Markdown 文件」导入时生效**，用于定位文章所属知识库目录；为空时落在知识库根目录。ZIP 导入按压缩包目录结构、**忽略**该字段 |

兼容与别名：

- `tags` 兼容别名：`articleTags`、`tagList`、`tagNames`；
- `columns` 兼容别名：`columnList`、`columnNames`；
- `createTime` 兼容别名：`create_time`、`createdAt`、`created_at`、`created`；
- `updateTime` 兼容别名：`update_time`、`updatedAt`、`updated_at`、`updated`、`modified`；
- `columns` 内重复项自动去重后依次处理。

时间字段规则（**重点**）：

- 标准格式为 `YYYY-MM-DD HH:mm:ss`（如 `2026-09-19 14:30:00`）；
- 同时兼容 `YYYY-MM-DD HH:mm`、`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY年MM月DD日` 等常见写法；
- 未提供 `createTime` 时取导入时间；未提供 `updateTime` 时取创建时间；
- 导入后归档分组、首页排序等都会按设置的真实时间生效。

专栏匹配规则（**重点**）：

- 专栏字段支持两种写法：
  - `父专栏/子专栏`：先按名称找到一级专栏，再在其下按名称找到子专栏；
  - `专栏名`：在所有层级中按名称匹配（**包含二级专栏**）；
- **只匹配、不创建**：数据库中已有则关联，没有则跳过（既不新建专栏，也不建立关联）；
- 该规则保证了二级专栏也能被正确匹配并统计文章数，避免因导入时新建同名一级专栏而导致二级专栏恒为 0 篇。

字段与博客属性映射：

| 元数据 | 博客字段 | 规则 |
| --- | --- | --- |
| `title` | `blog.title` | 标题即 title |
| `articleSummary` | `blog.description` | 描述即摘要；缺省时正文截取 |
| 正文首个图片 | `blog.first_picture` | 取正文中第一个图片链接（Markdown 或 HTML，取更靠前者） |
| `tags` | `tag` + `blog_tag` | 不存在则新建标签，再建立关联 |
| `category` | `category` + `blog.category_id` | 不存在则新建分类，再关联 |
| `columns` / `column` | `blog_column` + `blog_column_relation` | **只匹配已存在的专栏（含二级专栏）再关联；不存在则不关联、不新建** |
| `createTime` | `blog.create_time` | 创建时间；缺省为导入时间 |
| `updateTime` | `blog.update_time` | 更新时间；缺省同创建时间 |
| 导入参数 `published` | `blog.is_published` | 默认公开 |

### 4.3 代码块解析规则与边界

- **位置**：必须位于文件**最顶部**，允许前面存在空白字符/BOM；代码块之前不能有其他正文内容；
- **围栏**：起始围栏为 ``` 或 ```json（`json` 标记大小写不敏感），结束围栏为单独一行的 ```；
- **移除**：解析成功后，该代码块会从正文中移除，不会出现在文章内容里；
- **非法 JSON**：若代码块内容不是合法 JSON，则视为无元数据，代码块**保留在正文中**，标题回退为文件名；
- **无代码块**：整篇按纯 Markdown 处理，标题回退为文件名，分类使用默认「知识库」；
- **单篇唯一**：只解析最顶部第一个代码块。

### 4.4 文件与安全限制

| 项 | 限制 |
| --- | --- |
| ZIP 文件大小 | ≤ 500 MB |
| 单个 Markdown | ≤ 5 MB |
| 解压总大小 | ≤ 2 GB |
| 可导入目录+文档数 | ≤ 2000 |
| ZIP 原始 Entry 数 | ≤ 10000 |
| 路径最大深度 | ≤ 20 层 |
| 编码 | Markdown 必须为合法 UTF-8 |
| 路径安全 | 禁止绝对路径、盘符路径、`..`、`.`、空路径段、`\0` |
| 自动忽略 | `__MACOSX/` 及任一路径段以 `.` 开头的文件 |
| 重名路径 | ZIP 内重名路径（忽略大小写）直接判为非法 |

### 4.5 Markdown 文件导入（非 ZIP）与 knowledgeBasePath

「Markdown 文件」导入用于本地单篇 / 多篇 Markdown 的**增量平移导入**，没有压缩包目录结构，文章落点完全由元数据 `knowledgeBasePath` 决定：

- 单个或多个 `.md` 文件均可，单篇 ≤ 5 MB，总计 ≤ 100 MB，单次最多 2000 篇；
- `knowledgeBasePath` 为**知识库内的目录路径**，严格校验：
  - 必须以 `/` 开头、末尾不能带 `/`（标准形如 `/a/bb/cc`）；
  - 不允许空路径段（`//`）、`.`、`..`、反斜杠、空字符；层级 ≤ 20 层；
  - 为空（缺省）时落在**知识库根目录**；
- 目标目录不存在时，执行阶段会**按层级逐级自动创建**（已存在的同名目录复用）；
- 同一路径下文件名重复时，自动追加 ` (n)` 后缀，避免路径冲突；
- 文档节点名最终取元数据 `title`（缺省取文件名），目录名来自 `knowledgeBasePath` 各段。

示例：

```json
{
  "title": "SqlParser解析器快速入门",
  "knowledgeBasePath": "/a/bb/cc"
}
```

表示该文章会被放入知识库 `a/bb/cc` 目录（`a`、`bb`、`cc` 不存在则逐级创建）。

> 说明：ZIP 导入的目录来自压缩包文件夹，因此无需（也不使用）`knowledgeBasePath`；两种模式共用后续的博客入库、标签/分类/专栏关联与进度反馈逻辑。

## 五、标准导入流程

### 5.1 预检阶段（不写库）

1. 校验参数：`conflictPolicy` 仅允许 `SKIP`/`RENAME`；`published` 缺省 `true`；`targetParentId` 缺省 0；
2. 校验文件：非空、≤ 500MB、扩展名为 `.zip`；
3. 上传流写入临时文件；
4. 扫描 ZIP：过滤非法/隐藏文件，校验各文件大小、总量、数量、路径、UTF-8 编码与重名；
5. 归一化目录树：为每个文件补齐其父目录 Entry，按「深度升序 + 路径」排序，保证父目录先于子节点；
6. 生成一次性 `token`，缓存会话（临时文件、Entry 列表、参数），有效期 **30 分钟**；
7. 返回预检结果：`token`、`directoryCount`、`documentCount`、`ignoredCount`、`totalUncompressedBytes`、`paths`。

### 5.2 执行阶段（异步 + 事务）

1. 凭 `token` 取出会话（一次性，取出即失效），校验未过期；
2. 全局单任务互斥：同一时刻只允许一个导入任务，重复提交提示「当前已有知识库导入任务」；
3. 创建进度任务，提交到单线程执行器异步执行，立即返回 `taskId`；
4. 核心执行（单事务，任一失败整体回滚）：
   - 确定导入根目录（`targetParentId`，0 为根）；
   - 按排序后的 Entry 顺序，目录先建、文档后建；
   - 每个目录：同父级同名目录存在则复用，否则新建；
   - 每个文档：解析元数据 → 创建博客 → 关联标签/分类/专栏 → 将博客对应的知识库节点移动到目标目录；
   - 每处理一项推进一次进度；
5. 成功则任务置为 SUCCESS（进度 100%），失败则记录错误信息与当前文件路径；
6. 无论成功失败，删除临时 ZIP。

### 5.3 进度反馈

| 字段 | 含义 |
| --- | --- |
| `status` | PENDING / RUNNING / SUCCESS / FAILED |
| `progress` | 进度百分比（运行中最高 99%，完成后 100%） |
| `total` / `processed` | 待处理总数 / 已处理数 |
| `currentPath` | 当前处理的文件路径 |
| `createdDirectoryCount` | 已创建目录数 |
| `createdBlogCount` | 已创建博客数 |
| `skippedCount` | 因冲突策略跳过数 |
| `message` | 状态文案（等待导入/正在导入/导入完成/失败原因） |

> 进度任务保存在内存中，完成 30 分钟后自动清理；服务重启后任务丢失。

## 六、核心处理逻辑

### 6.1 目录处理

- 同父级下同名目录存在则**复用**（目录天然幂等，不做重命名）；
- 不存在则新建 `DIR` 节点，排序取当前父级最大 `sort + 1`，追加到末尾；
- 记录「导入路径 → 目录节点 ID」，供子节点解析父目录；
- ZIP 模式的目录来自压缩包文件夹结构；**文件模式**的目录来自每篇 `knowledgeBasePath`，缺失目录在执行阶段逐级自动创建。

### 6.2 文档处理（逐篇）

1. **解析元数据**：读取顶部代码块，得到 `metadata` 与去掉代码块的正文 `content`；
2. **确定标题**：`metadata.title`，缺省回退文件名；
3. **冲突处理**：目标目录下同名文档时，SKIP 跳过 / RENAME 生成 `原名 (n)`；
4. **确定描述**：`metadata.articleSummary`，缺省由正文剥离 Markdown 标记后截取前 200 字；
5. **确定首图**：取正文中第一个图片链接（Markdown `![](url)` 或 HTML `<img src>`，取出现更靠前者），无则空串；
6. **解析标签**：逐个按名称查库（忽略大小写），不存在则新建，同篇去重，超长截断 100 字；
7. **解析分类**：按名称查库，不存在则新建；缺省使用「知识库」；
8. **解析专栏**：`column` + `columns` 合并去重，逐个按「父/子路径」或「全层级名称」匹配**已存在**的专栏（含二级专栏），匹配到则关联，匹配不到则跳过（不新建）；
9. **解析时间**：`createTime` / `updateTime` 按 `YYYY-MM-DD HH:mm:ss` 解析，缺省时创建时间取当前时间、更新时间同创建时间；
10. **保存博客**：标题、正文、描述、首图、分类、专栏、创建/更新时间、发布状态等一次性写入，并创建对应的知识库 `DOC` 节点；
11. **关联标签**：逐条写入 `blog_tag`；
12. **挂载节点**：把该博客的 `DOC` 节点移动到目标目录并更新节点名；
13. **推进进度**。

### 6.3 博客字段默认值

| 字段 | 默认值 |
| --- | --- |
| `is_published` | 由导入参数 `published` 决定，默认 `true`（公开） |
| `is_recommend` / `is_appreciation` / `is_top` | `false` |
| `is_comment_enabled` | `true` |
| `views` / `password` | `0` / 空串 |
| `words` / `read_time` | 由正文去空白后字符数计算（约 200 字/分钟） |
| `create_time` / `update_time` | 取元数据 `createTime` / `updateTime`；缺省时创建时间取导入时间、更新时间同创建时间 |
| 作者 | 系统管理员（用户 ID=1） |

### 6.4 冲突策略

| 策略 | 行为 |
| --- | --- |
| SKIP（默认） | 目标目录下已存在同名文档则跳过，不创建、不覆盖，计入 `skippedCount` |
| RENAME | 目标目录下已存在同名文档则生成 `原名 (1)`、`原名 (2)` … 直到不重名 |

> 目录不做冲突重命名，始终复用同名目录；仅文档参与冲突策略。

## 七、校验与错误提示（用户可见）

| 场景 | 提示 |
| --- | --- |
| 未选择文件 | 请选择 ZIP 文件 / 请选择 Markdown 文件 |
| 文件超限 | ZIP 文件不能超过 500 MB / Markdown 文件不能超过 5 MB |
| 非 ZIP | 仅支持 ZIP 文件 |
| 非 Markdown | 仅支持 .md 文件 |
| 文件数量超限 | 单次最多导入 2000 个 Markdown 文件 |
| 文件总量超限 | Markdown 总大小超过 100 MB，请改用 ZIP 导入 |
| knowledgeBasePath 非法 | knowledgeBasePath 必须以 / 开头 / 末尾不能带 / / 不能包含空路径段 / 不能包含 . 或 .. / 目录深度超过 20 |
| 无有效内容 | ZIP 中没有可导入的 Markdown 或目录 |
| Markdown 超限 | Markdown 文件不能超过 5 MB |
| 总量超限 | Markdown 解压总大小超过限制 |
| 数量超限 | 可导入目录和 Markdown 数量超过 2000 |
| Entry 超限 | ZIP 原始 Entry 数量超过 10000 |
| 层级超限 | ZIP 目录深度超过 20 |
| 编码非法 | Markdown 不是有效 UTF-8 编码 |
| 路径非法 | ZIP Entry 路径不合法 / ZIP 不能包含绝对路径 |
| ZIP 内重名 | ZIP 内存在重名路径 |
| 目标目录不存在 | 导入目标目录不存在 |
| 会话失效 | 预检会话已过期或已提交 |
| 任务繁忙 | 当前已有知识库导入任务 |
| 参数非法 | 导入参数不能为空 / 冲突策略不正确 |

---

## 八、边界与限制

- 导入是**追加**行为，不删除目标库中已有博客或目录；
- 不支持图片、附件导入，也不改写 Markdown 内的相对资源链接；
- 不解析 Front Matter，元数据统一使用顶部 JSON 代码块；
- 一个文档节点只关联一篇博客；
- 同一时刻仅允许一个导入任务；预检 token 一次性、30 分钟有效；
- 进度任务为内存态，服务重启后不可恢复；
- 导入失败时整体回滚，不产生半成品数据。

---

## 九、导出与互逆

- 整库导出：目录导出为文件夹、文档导出为 `.md`，命名为 `blogloom-knowledge.zip`；
- 单文档导出：下载该文档对应博客的 Markdown 正文；
- 导出内容**不包含**顶部元数据代码块（元数据来自博客字段，导入时可再次补全）；
- 导出后重新导入，可还原目录层级、节点名与正文。

---

## 十、验收标准

1. 上传含多级目录与 Markdown 的 ZIP，预检统计与路径列表正确；
2. 目录层级与 ZIP 文件夹结构一致，父目录先于子节点创建；
3. 每篇 Markdown 生成一篇博客，标题取 `title`（缺省取文件名）；
4. 顶部代码块被正确解析且**不出现**在文章正文中；
5. `tags` 3-5 个、`category` 单个、`columns` 多个均能正确解析；
6. 标签/分类在库中不存在时自动创建并建立关联，已存在时复用不重复创建；专栏只关联已存在的（含二级专栏），不存在的跳过且不新建；
7. 文章描述取 `articleSummary`，缺省时自动截取正文；
8. 文章首图取正文第一个图片链接；
9. `createTime` / `updateTime` 按 `YYYY-MM-DD HH:mm:ss` 写入博客创建/更新时间，缺省时使用导入时间；
10. `published` 关闭时导入博客为私密，开启时为公开；
11. SKIP 策略跳过同名文档，RENAME 策略生成 `(n)` 后缀且不覆盖；
12. 执行过程中进度、当前文件与计数实时更新，完成后展示最终统计；
13. 任一校验/执行失败时给出明确提示且事务回滚，无脏数据；
14. 导出 ZIP 再导入，目录与正文可还原；
15. 选择单个/多个 Markdown 文件导入时，文章按各自 `knowledgeBasePath` 落入对应知识库目录，缺失目录逐级自动创建；
16. `knowledgeBasePath` 为空时文章落在知识库根目录；格式非法时预检直接报错并给出原因；
17. ZIP 导入时忽略 `knowledgeBasePath`，目录仍严格按压缩包文件夹结构还原。

## 常见问题（FAQ）

**Q1：导入后，每篇 Markdown 顶部的代码块会保留在正文里吗？**

A：解析成功时**会从正文中移除**，不会出现在文章内容里（见 4.3 代码块解析规则与边界）。
仅以下两种情况代码块会保留在正文：

- 代码块内容**不是合法 JSON** → 视为无元数据，代码块原样保留，标题回退为文件名；
- 文件顶部**没有代码块** → 按纯 Markdown 处理，正文原样。

**Q2：作为首图的第一张图片会被从正文删除吗？**

A：**不会**。首图仅“读取”正文中第一个图片链接并写入 `blog.first_picture`，正文 `content` 原样保留，该图片仍会显示在文章内容中。
即导入后效果为：封面 = 正文第一张图，且正文里那张图依然存在。

> 如需“首图只作封面、并从正文中移除”，当前未实现，需要额外扩展导入逻辑。

**Q3：`columns` 里的专栏会自动创建吗？二级专栏能匹配到吗？**

A：**不会自动创建**。专栏采用「只匹配、不创建」：数据库中已有同名专栏则建立关联，没有则跳过。
匹配时支持两种写法：

- `父专栏/子专栏`：精确定位到某个二级专栏；
- `专栏名`：在所有层级中按名称匹配，**包含二级专栏**。

> 因此导入前请先创建好专栏（可在「专栏管理」手动创建，或用专栏 ZIP 导入），否则文章不会关联到专栏。
> 修正说明：早期实现只在“一级专栏”中匹配、匹配不到就新建，导致元数据写二级专栏名时会被建成同名一级专栏，原二级专栏文章数恒为 0；现已改为全层级匹配且不自动创建。
