# 访客地图二期：海外城市字典扩充与海外行政区悬停高亮设计

> 一期解决的是“能不能把全球访客画到地球上”；二期解决的是“海外城市点得出来、海外行政区看得懂”。
>
> 本文只做两件事：
>
> 1. 后端：把 `visitor_geo` 从 20 个海外城市样例扩充到覆盖 45 个热门国家的 246 个海外城市行，并让城市匹配能利用省州名消歧。
> 2. 前端：让美国、加拿大、澳大利亚、巴西、法国、德国、印度、日本、英国、新加坡的 ADM1 行政区像中国省份一样有板块填充、悬停高亮；有 PV/UV 的行政区才显示名称与数字，没有数据的行政区只高亮、不弹数据。

---

## 一、现状与问题

一期上线后，地图已经具备完整的采集、定位、落库、聚合、渲染链路，但海外部分仍有三处明显短板：

| 问题 | 一期现状 | 用户感知 |
| --- | --- | --- |
| 海外城市字典太小 | 只有 20 个海外城市行 | 除少数首都/知名城市外，海外访客只能落到国家级，地图上只有板块热度，没有城市光点 |
| 城市名与 ip2region 不一致 | 例如库里是 `New York`、`Sao Paulo`，ip2region 输出 `New York City`、`São Paulo` | 明明有城市行，却匹配不上，命中率被白白拉低 |
| 海外 ADM1 只有描边 | `drawAdm1()` 只画州/省边界线，没有填充，也没有命中检测 | 鼠标移到美国州、日本都道府县上没有任何反馈，和中国省份的体验不一致 |
| 省州名来源不统一 | `visitor_geo.region_name` 一期海外城市为 `NULL`；ip2region 的省州名与 geoBoundaries 的 ADM1 名也不完全一致 | 即使画了板块，也算不出“哪个州有访客”，无法着色 |

二期不改变一期的统计口径，只补数据密度和交互层。

## 二、后端部分

### 2.1 扩充原则

`visitor_geo` 是维表，不是全量世界城市库。二期仍然坚持一期定下的取舍：

1. **只收录热门国家的主要城市**，不追求与 ip2region 的 2.3 万个海外城市一一对应。
2. **`city_name_en` 必须与 ip2region v4 实际输出完全一致**，包括空格、重音符号、缩写和 `City` 后缀。
3. **`region_name` 存 ip2region 输出的省州名**，用于同名城市消歧，也作为前端 ADM1 统计的第一优先键。
4. **`geo_key` 保持稳定**，新行统一使用 `<国家码>|CITY|<国家码>-X-<序号>`，与一期 `US-012`、`CN-003` 等序号不冲突。
5. **坐标使用 WGS84**，城市级必须有经纬度；国家级行仍然只做聚合兜底，不带坐标。
6. **脚本可重复执行**，统一使用 `ON DUPLICATE KEY UPDATE`。

### 2.3 名称对齐：比坐标更容易出错的地方

本次 SQL 不是简单翻译城市名，而是先用 ip2region v4 XDB 反查真实输出，再按输出值建行。几个典型坑：

| 城市 | 一期值 | ip2region 实际输出 | 处理 |
| --- | --- | --- | --- |
| 纽约 | `New York` | `New York City` | 更新 `US|CITY|US-035` 的 `city_name_en` |
| 圣保罗 | `Sao Paulo` | `São Paulo` | 更新 `BR|CITY|BR-016`，补重音 |
| 科隆 | 无 | `Köln` | 新增行使用 `Köln`，不要写 `Cologne` |
| 纽伦堡 | 无 | `Nürnberg` | 新增行使用 `Nürnberg`，不要写 `Nuremberg` |
| 蒙特利尔 | 无 | `Montréal` | 保留重音 |
| 魁北克城 | 无 | `Québec` | 保留重音，和城市 `Montréal` 区分 |
| 顺化 | 无 | `Huế` | 保留越南语重音 |
| 伊兹密尔 | 无 | `İzmir` | 保留土耳其语 `İ` |
| 格但斯克 | 无 | `Gdańsk` | 保留波兰语变音 |
| 苏黎世 | 无 | `Zuerich` | 使用 ip2region 的转写，不要写 `Zürich` |
| 哥德堡 | 无 | `Goeteborg` | 使用 ip2region 的转写，不要写 `Gothenburg` |
| 奥胡斯 | 无 | `Aarhus Kommune` | 使用 ip2region 的完整城市名 |
| 海防 | 无 | `Haiphong` | 城市名用 `Haiphong`，省州名用 `Hai Phong` |

**结论：** 海外城市行的 `city_name_en` 不是“展示名”，而是“匹配键”。展示层需要更自然的名字时，应在展示层做映射，不要反过来改匹配键。

### 2.4 匹配增加省州消歧

一期 `findCityGeoId` 只按 `city_name_zh / city_name_en + country_code` 匹配。海外城市扩充后，同名城市会变多，例如：

- `Portland`：Oregon / Maine
- `Oakland`：California / New Jersey / Mississippi
- `Cambridge`：Massachusetts / 英国
- `Victoria`：British Columbia / Texas

二期在 Mapper 上增加 `regionName` 参数，并优先选择省州匹配的行：

```xml
<select id="findCityGeoId" resultType="long">
    SELECT id
    FROM visitor_geo
    WHERE geo_level = 2
      AND (city_name_zh = #{cityName} OR city_name_en = #{cityName})
    <if test="countryCode != null and countryCode != ''">
      AND country_code = #{countryCode}
    </if>
    ORDER BY
    <if test="regionName != null and regionName != ''">
      CASE WHEN region_name = #{regionName} THEN 0 ELSE 1 END,
    </if>
      id
    LIMIT 1
</select>
```

调用方从五段文本里同时取第二段省州和第三段城市：

```java
String region = fields.length > 1 ? fields[1].trim() : "";
String city = fields.length > 2 ? fields[2].trim() : "";
geoId = visitorGeoMapper.findCityGeoId(city, countryCode, region);
```

这样即使同一个国家里有同名城市，也会优先命中省州一致的那一行；省州对不上时仍然回退到“城市 + 国家”匹配，不会因为省州命名差异直接丢失城市命中。

## 三、前端部分

### 3.1 目标交互

二期的交互目标只有一句话：

> 海外 ADM1 行政区要像中国省份一样“有块、有亮、有数据才说话”。

| 场景 | 一期 | 二期 |
| --- | --- | --- |
| 有访客的行政区 | 只有边界线 | 按 UV 热度填充，悬停加深，Tooltip 显示城市数与最高 UV |
| 没有访客的行政区 | 只有边界线 | 低透明度填充；悬停高亮；不弹 Tooltip |
| 城市光点 | 有 | 不变，城市命中优先于行政区 |
| 中国省份 | 填充 + 悬停 + Tooltip | 不变 |

### 3.2 ADM1 索引与 bbox

`adm1-mvp.js` 里的数据结构是：

```js
window.BLOGLOOM_ADM1 = {
  USA: [{name: 'California', center: [...], rings: [[[lng, lat], ...]]}],
  JPN: [{name: 'Tokyo', center: [...], rings: [...]}],
  // ...
}
```

渲染器启动时把 10 个国家的 226 个行政区展开成一维索引，并预计算 bbox：

```js
const adm1Regions = []
Object.entries(adm1ByCountry).forEach(([iso3, regions]) => {
    const countryCode = ADM1_COUNTRY_CODE[iso3]
    if (!countryCode) return
    regions.forEach(region => {
        // 计算 minLng / minLat / maxLng / maxLat
        adm1Regions.push({
            countryCode,          // ISO2，用于和 cities[].countryCode 对齐
            countryIso3: iso3,    // 用于取 ADM1 颜色
            name: region.name,    // geoBoundaries 原始名
            key: `${iso3}|${normalizeRegionName(region.name)}`,
            rings: region.rings,
            bbox: [minLng, minLat, maxLng, maxLat]
        })
    })
})
```

bbox 的作用和一期中国省份一样：悬停时先用矩形粗筛，再做 `pointInRing` 精判，避免每次 `mousemove` 都遍历全部环。

### 3.3 省州名归一化

这是二期前端最关键的一步。ip2region 的省州名和 geoBoundaries 的 ADM1 名并不总是一致：

| ip2region 输出 | geoBoundaries ADM1 | 问题 |
| --- | --- | --- |
| `Bavaria` | `Bayern` | 英文名 vs 德文名 |
| `Hesse` | `Hessen` | 英文名 vs 德文名 |
| `North Rhine-Westphalia` | `Nordrhein-Westfalen` | 英文名 vs 德文名 |
| `Saxony` | `Sachsen` | 英文名 vs 德文名 |
| `Lower Saxony` | `Niedersachsen` | 英文名 vs 德文名 |
| `Thuringia` | `Thüringen` | 英文名 vs 德文名 |
| `Rhône-Alpes` | `Auvergne-Rhône-Alpes` | 旧大区名 vs 新大区名 |
| `Washington, D.C.` | `District of Columbia` | 城市名 vs 特区名 |
| `Rio de Janeiro` | `Rio de Jeneiro` | 上游拼写错误 |
| `Maharashtra` | `Mahārāshtra` | 变音符号 |
| `Tamil Nadu` | `Tamil Nādu` | 变音符号 |
| `Osaka` | `Osaka Prefecture` | 后缀差异 |
| `State of Berlin` | `Berlin` | 前缀差异 |

前端采用“**三级归一 + 兜底反查**”：

**第一级：字符归一**

```js
function normalizeRegionName(name) {
    const text = String(name || '')
    const plain = typeof text.normalize === 'function'
        ? text.normalize('NFD').replace(/[\u0300-\u036f]/g, '')  // 去掉重音
        : text
    return plain
        .toLowerCase()
        .replace(/^state of\s+/, '')                              // State of Berlin
        .replace(/\b(prefecture|province|state|region|governorate|department|district|county|voivodeship|municipality)\b/g, '')
        .replace(/[^a-z0-9]+/g, '')                              // 去空格和标点
}
```

**第三级：坐标反查兜底**

如果归一化后的 key 在 ADM1 索引里找不到，就拿城市坐标做一次 `adm1RegionByPoint` 反查。这样即使省州名完全对不上，只要坐标落在某个行政区内，仍然能算出该区的统计值。

```js
function buildAdm1Stats(list) {
    const stats = new Map()
    list.forEach(city => {
        const iso3 = COUNTRY_ISO3[city.countryCode]
        if (!iso3) return
        const aliases = REGION_NAME_ALIASES[iso3] || {}
        const alias = aliases[normalizeAliasKey(city.regionName)]
        let key = `${iso3}|${normalizeRegionName(alias || city.regionName)}`
        if (!adm1RegionKeys.has(key)) {
            const region = adm1RegionByPoint(city.lat, city.lng, city.countryCode)
            if (!region) return
            key = region.key
        }
        const item = stats.get(key) || {cityCount: 0, maxUv: 0, pv: 0}
        item.cityCount += 1
        item.maxUv = Math.max(item.maxUv, Number(city.uv) || 0)
        item.pv += Number(city.pv) || 0
        stats.set(key, item)
    })
    return stats
}
```

### 3.4 绘制：填充、热度和悬停

一期 `drawAdm1()` 只描边。二期改成逐区绘制：

```js
function drawAdm1() {
    if (state.zoom < 0.82 || state.dragging) return
    adm1Regions.forEach(region => {
        const stats = adm1Stats.get(region.key)
        const hovered = hoveredRegionKey === region.key
        context.beginPath()
        traceFeatures([region])
        if (stats) {
            context.fillStyle = heatColor(stats.maxUv, hovered ? 0.72 : 0.4)
        } else {
            context.fillStyle = hovered ? 'rgba(44, 68, 170, .62)' : 'rgba(16, 44, 74, .14)'
        }
        context.fill('evenodd')
        context.strokeStyle = hovered ? '#8df2ff' : (ADM1_COLORS[region.countryIso3] || '#4daecd')
        context.lineWidth = hovered ? 1.3 : (state.zoom > 1.4 ? 0.9 : 0.55)
        context.stroke()
    })
}
```

三个视觉层级：

| 状态 | 填充 | 描边 | 说明 |
| --- | --- | --- | --- |
| 无数据、未悬停 | `rgba(16, 44, 74, .14)` | 国家色，低透明度 | 保持板块可辨认，不抢光点 |
| 无数据、悬停 | `rgba(44, 68, 170, .62)` | `#8df2ff`，1.3px | 只高亮，不弹数据 |
| 有数据、悬停 | `heatColor(maxUv, .72)` | `#8df2ff`，1.3px | 高亮 + Tooltip |

热度仍然复用一期的 `heatColor()`，和城市光点、国家板块共用同一套 `maxUv`，保证颜色含义一致。

### 3.5 命中顺序

`pointermove` 的命中顺序固定为：

```text
城市光点（28px 屏幕距离）
  ↓ 未命中
中国省份（逆投影 → bbox → pointInRing）
  ↓ 未命中
海外 ADM1 行政区（逆投影 → bbox → pointInRing）
  ↓ 未命中
清空 hover
```

对应代码：

```js
const city = nearestCity(event.clientX, event.clientY)
if (city && cityStats.get(city.city)) {
    hoveredRegionKey = null
    notifyHover({city, stats: cityStats.get(city.city), ...})
    return
}

const province = provinceAt(event.clientX, event.clientY)
if (province && provinceStats.get(normalizeProvinceName(province))) {
    hoveredRegionKey = null
    notifyHover({province, provinceStats, ...})
    return
}

const region = adm1RegionAt(event.clientX, event.clientY)
hoveredRegionKey = region ? region.key : null
const regionStats = region ? adm1Stats.get(region.key) : null
notifyHover(regionStats ? {region: region.name, regionStats, ...} : null)
```

**Tooltip 规则：**

| hover 负载 | 页面表现 |
| --- | --- |
| `{city, stats}` | 城市名 + 访客数 |
| `{province, provinceStats}` | 省名 + 访客城市数 / 最高 UV |
| `{region, regionStats}` | 行政区名 + 访客城市数 / 最高 UV |
| `null` | 不显示 Tooltip；行政区仍然保持悬停高亮 |

这正好满足“有 PV/UV 才显示名字 + 数字，没有数据只亮不弹”的规则。

### 4.3 数据构建方式

构建脚本已落地：

```text
blog-cms-ui/scripts/build-adm1-data.js
```

实际流程：

```text
① 读取国家列表（默认 P1 十国，可用 --countries= 覆盖）
② 请求 https://www.geoboundaries.org/api/current/gbOpen/{ISO3}/ADM1/
③ 从返回 JSON 里取 simplifiedGeometryGeoJSON
④ 环抽稀：Douglas-Peucker（tolerance 0.012）+ 最多 80 点/环
⑤ 过滤面积过小的岛屿环（minArea 0.004 平方度）
⑥ 输出 { ISO3: [{name, center, rings}] }
⑦ 写入 data/adm1-extended.js，并用 Object.assign 合并到 window.BLOGLOOM_ADM1
```

常用命令：

```bash
# 重新生成 P1 十国（默认输出 adm1-extended.js）
npm run build:adm1
# 等价于 node scripts/build-adm1-data.js

# 只生成指定国家，并输出到新的批次文件
node scripts/build-adm1-data.js --countries=NLD,ESP,ITA --output=src/components/VisitorGlobe/data/adm1-europe.js

# 追加新批次（生成结果始终合并到 window.BLOGLOOM_ADM1）
node scripts/build-adm1-data.js --countries=PRT,IRL,NOR
```

脚本运行需要 Node 18+（使用全局 `fetch`）。生成结果始终以 `Object.assign` 合并，不会覆盖 `adm1-mvp.js` 已注册的国家。

两个实现细节：

1. **原始数据缓存**：下载结果写入 `blog-cms-ui/.cache/adm1/`，已加入 `.gitignore`；重复构建不重复下载。
2. **数据源覆盖**：geoBoundaries gbOpen 的 `ITA/ADM1` 只有 5 个大区（Nord-Ovest / Nord-Est / Centro / Sud / Isole），与 ip2region 的 20 个大区粒度不一致。脚本内置 `SOURCE_OVERRIDES`，意大利改用 [openpolis/geojson-italy](https://github.com/openpolis/geojson-italy) 的 20 个大区（CC-BY，数据源 ISTAT）。

```js
const SOURCE_OVERRIDES = {
    ITA: {
        url: 'https://raw.githubusercontent.com/openpolis/geojson-italy/master/geojson/limits_IT_regions.geojson',
        nameField: 'reg_name'
    }
}
```

## 六、取舍与风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 城市名仍可能对不上 | ip2region 的城市名存在转写、重音、拼写差异 | 以 XDB 实际输出为准；新增城市前先反查 |
| 省州名对不上 | ip2region 与 geoBoundaries 命名体系不同 | 字符归一 + 别名 + 坐标反查三级兜底 |
| ADM1 填充影响观感 | 无数据行政区也会填充，可能让地球变“花” | 无数据填充透明度压到 0.14，悬停才提亮 |
| ADM1 数据体积增长 | 扩展到 P2/P3 后可能超过 1MB | 分批、按大区分文件、按国家动态加载 |
| 同名城市消歧不完美 | 省州名不一致时仍可能命中同国同名城市 | 优先省州匹配，保留城市 + 国家回退 |
| 行政区中文名缺失 | ADM1 名称主要是源数据语言 | 二期先显示源名；后续补 `region_name_zh` 映射表 |
